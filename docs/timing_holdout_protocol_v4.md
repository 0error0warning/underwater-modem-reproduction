# V4 主峰定时：新记录验证预注册

本计划在读取或下载本轮 011–020 的信道内容之前固定。它检验 V3 开发诊断中的主峰候选，不能把原始开发结果当作本轮验证结果。运行代码、分析代码、接收器依赖和本文件的 SHA-256 写入 `results/v4/timing_holdout/freeze.json`，在下载新记录前提交 Git；正式运行前后重新核验。

## 数据划分与范围

- 001–010：此前开发数据；本轮只用 001 做实现等价自检。
- 031–040：此前 V2 已评测数据，不能重新称为未见测试集。
- **NOF1、NCS1 的 011–020**：本轮预先指定的新记录，每类 10 条。每条取与旧流程相同的前 32 s，5 个 6.4 s 槽位。
- **两类 021–030 保留**：本轮不下载、不读取、不统计。
- Watermark 相邻记录可能来自同一环境/航次，不能把 20 条记录称为 20 个独立海域，也不能据此声称硬件、水池或广泛环境泛化。

## 固定算法与实验条件

比较 `uac4.receive_timing(rx,cfg,64,'first')` 与 `...,'strong'`。两者使用完全相同的收到波形、HFM 检测、导频尺度估计、Lanczos 分数采样和精确双音能量检测器。`first` 直接返回冻结的 V2 首到达峰接收结果；`strong` 只将有效符号积分起点替换为 V2 已计算出的、尺度精化后的 HFM 联合检测主峰。没有载荷真值、信道响应或真实速度进入接收接口，没有按 BER 搜索定时。

固定 48 kHz、13,875/14,125 Hz、每包 64 bit、各符号复位到同一包初相。主条件为 **NOF1、4 ms 发声、0 ms 保护**；NCS1 的相同条件和两类信道的 4/4、8/0、8/8 ms 是预定次要条件，不据结果删除。每条件每信道 10×5=50 包、3,200 bit，共 400 个波形、800 条方法观测。

采用 V3 的固定随机数规则：基种子 2026110205；发端种子为 `base + channel_index*10000000 + record*10000 + slot`（NOF1=1、NCS1=2）。产生比特后，起点抖动为 `3*round((0.12+0.22*rand)*fs/3)` 样本，包初相为 `2*pi*rand`。噪声种子为 `base + channel_index*10000000 + record*10000 + slot*100 + 20 + 50`。所有配置相同事件共享比特、初相和单位噪声；噪声方差随配置按既定定义标定，**只有同配置的两种接收方法严格同波形配对**。

噪声固定为旧诊断的 `sample_snr_packet` 20 dB：恢复整体多普勒后，`variance=sum(clean.^2)/ceil((packet_duration_s+0.128)*alpha_true*fs)/100`。信道真值只用于生成收到波形与记录仿真标签，接收器不使用。该 SNR 是接收参考包功率定义，不等于论文未明确给出的噪声口径。每包尺度恢复沿用旧流程；本轮不重做连续排程或自适应策略。

## 统计、失败与解释

每包保留 `detected`、错误比特、擦除比特、总比特、包错误、初相、噪声方差、收到波形 SHA-256、估计尺度和定时。不捕获或解码长度不完整时，整包 64 bit 记为擦除，包错误记为 1；不默默丢弃。

主要描述指标为总比特损失率 `(errors+erasures)/total_bits`，同时列出已解码比特的 BER、擦除率和 PER。没有擦除时比特损失率等于 BER。按每条信道记录先聚合 5 包，再报告配对差异、改善/持平/恶化记录数、差异范围及中位数。总量和逐记录结果同时展示，避免平均数掩盖少数严重退化记录。

主假设方向预先固定：NOF1 4/0 的主峰规则比首到达规则具有更低的合计比特损失率。结果无论正负都保留；次要条件用于观察外推边界，不用于重选参数。若主条件改善，也只支持这批新记录上的该条件结论；跨条件出现恶化时必须明确报告，不自动替换全信道基线。记录相关性与每条件仅 10 条记录限制推断，本轮不给独立比特二项置信区间或跨海域显著性结论。

实现检查失败可以在读取新数据前修复并重新冻结。读取新数据后若发现实现错误，须保留该轮日志和结果，记录修复原因并标为错误修正重分析；不能修改定时阈值、频率、噪声定义或记录选择来追求正结果。
