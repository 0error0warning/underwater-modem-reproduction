# V2 自适应保护时间：预先锁定的实验协议

协议版本：1.0；锁定日期：2026-11-02。本协议在读取 V2 最终留出数据前写定。分析脚本将协议 SHA256、开发数据 SHA256、规则和候选评分写入 `frozen_policy.json`；最终评测必须读取该冻结文件，不能在最终数据上改阈值。

## 问题与范围

在有效发射时间固定为 8 ms 的 BFSK 链路中，用**上一包接收前导**得到的信息，为下一包选择保护时间，能否改善单位占用时间内正确接收的载荷量？候选保护时间固定为 0、4、8、16、32 ms。同步、多普勒估计和载荷解调来自 V2 接收器；这个实验不重新优化它们。

主选择条件为同记录固定噪声参考、20 dB 标签、`sync_compensated` 接收器。冻结后的策略也应用于同一噪声定义下其他信噪比，作为预先规定的鲁棒性检查；不为各测试信噪比重新训练。这个 dB 标签依然不等于未披露定义的论文 SNR。

## 数据划分

|用途|NOF1 与 NCS1 的记录编号|作用|
|---|---|---|
|训练|001–005|确定固定回退动作，生成和拟合阈值候选|
|验证|006–010|在有限候选中选择规则及固定策略|
|时间隔离|011–030|不使用|
|最终留出|031–040|模型冻结后才计算结果|

001–010 在第一轮复现中已见过，因此训练/验证均属于开发数据。031–040 是同一次测量序列的较晚时间段，不能据此声称跨海域或任意环境泛化。训练与验证文件应与最终文件分开。

## 规则、拟合与因果顺序

可用特征只有上一包的 `delay_spread_ms`、`sync_score` 或 `abs(velocity_hat)`。每条规则最多一个阈值、两个叶子；信道名称、真实冲激响应、真实速度和当前包载荷真值均不作为策略输入。信道名称仅用于分组、配对与报告。

1. 训练数据中，计算五种恒定保护时间的总体无错载荷率，最高者为首包和缺失特征的回退动作。
2. 各特征从训练前导估计值的 10%–90% 分位数生成九个阈值候选。阈值两侧动作各从五种保护时间中选择；至少有八个有历史观测的训练事件落在每侧。动作相同的规则不当成自适应候选。
3. 逐个候选递归回放：首包使用回退动作；收到上一包实际所选保护时间对应的前导后，为下一包选择动作。上一包捕获失败、特征缺失或非有限值时回退。候选评分使用训练载荷结果，但这些真值只用于离线拟合，不传给运行时决策。
4. 每个特征只保留训练评分最好的一个规则。验证集在这最多三个规则中选出 `adaptive_stump`，并在五种恒定策略中选出 `best_fixed`；另记录验证在这两者中选择的 `validation_selected`。若验证支持固定策略，明确报告，而不隐去失败的自适应尝试。
5. 阈值候选生成可以利用训练实验测得的各个动作的前导；所有候选评分与最终回放均只使用上一包**实际选中动作**的前导，不引入免费的额外探测。

评分为 `无错误包的载荷 bit 总量 / 总占用时间`；并列时优先较简单规则，再用固定、可重复的次序。规则数、候选分位数和特征列表均不随最终结果改变。无需训练大型模型。

## 公平对照与时间预算

对照包含固定 0/8/32 ms、开发数据选出的 `best_fixed`、`adaptive_stump`、`validation_selected`。另计算知道当前包所有反事实结果后选择动作的 oracle，明确它不可部署，也不参与模型选择。

每个方案的 `occupied_s` 都包含驱动记录的前导/导频、载荷、符号保护及包尾开销，另统一计 **16 bit / 100 bit/s = 0.16 s** 的理想 ACK/模式通知预算。固定策略也需 ACK；自适应模式可以搭载在相同控制预算内。这个假设不代表回传物理链路已实现或已测量。

另外只给自适应增加 **0、0.16、0.5、1.0 s/包**，在同一组包结果上重算时间分母，报告控制/传播等待代价的敏感性；这不重新模拟多等待后变化的信道。它不穷尽真实水声往返传播时延；应根据未来实际距离重新计算。策略为一包延迟且按序回放，不使用收到当前前导之后才决定当前已发出的保护时间。

为控制信道时刻，实验在固定槽位测量所有候选动作的反事实结果。必须同时报告两种时间口径：**共同实验时间轴载荷率**以全部 `slot_s`（本轮每槽 6.4 s）为分母，保留所有空闲；**反事实占用效率**以 `occupied_s + 0.16 s` 为分母，仅用于估算假定可去掉实验空闲后的效率。训练目标是后者。两者都不能混称为已实现的实时网络吞吐量；改变保护时间后真实连续发包时刻和经历的信道也会变化。结果属于理想反馈模型下的离线因果策略回放；若后续另做连续时序实验，其结果应独立报告。

## 失败和统计

- 捕获失败：记一包失败、128 bit（或实际载荷数）擦除，不虚构为已解出的 0 个错误比特。
- 条件 BER：仅在成功捕获并得到载荷判决的比特上计算；同时报告捕获丢失率、包失败率、擦除 bit 数和无错载荷率。
- 一个包出现任何载荷错误即贡献 0 个有效载荷 bit。没有假定 CRC 已经实现，成功与否仍由仿真真值核查。
- 按信道分别重采样整条记录，在相同重采样记录上比较自适应与 `best_fixed` 的载荷率差值，使用固定种子和 2,000 次重复。报告 2.5%/97.5% 分位范围；相邻记录可能相关，它是记录重采样敏感性范围，不是跨环境泛化保证。
- 不承诺自适应一定改善。改进幅度、失败模式、控制开销和不能证明的结论都保留。

## 输入、冻结与输出

输入 CSV 至少包含 `channel,record,slot,on_ms,guard_ms,snr_db,noise_mode,receiver_mode,detected,payload_bits,bit_errors,bit_erasures,packet_error,occupied_s,slot_s,delay_spread_ms,sync_score,velocity_hat`。同一记录/槽位/SNR 下必须有五种保护时间，并使用相同输入载荷及匹配的噪声安排。若有 `trial` 或 `replicate`，它们也属于轨迹标识。

```powershell
python tools/analyze_adaptive_v2.py --stage fit --records results/v2/records_development.csv
python tools/analyze_adaptive_v2.py --stage evaluate --records results/v2/records_test.csv
```

输出目录为 `results/v2/adaptive`：冻结模型、候选开发评分、测试逐包动作与结果、测试汇总、记录重采样差值、控制开销敏感性、PNG/SVG 图和中文报告。脚本拒绝在拟合输入中包含 031–040，或在最终输入中混入开发记录。
